Review of #764 on 2026-11-21 (follow-up to [[postmerge-746-748-2026-11-21]]).

- **`position: static` voids `z-index`.** The header's `--z-header` only works while it is positioned. Made static (now at every 200%+ phone and laptop text size, not only sideways phones), the phone menu (`.nav-sheet`, absolute, z auto) paints under the fixed cookie sheet (z header-5): at 375x667/200% the menu's lower half (y 367 to 667) is covered. Keyboard Tab hid nothing (the page scrolls the static header and menu up); touch readers see half a menu. Fix: `position: relative` in the short-screen query (scrolls away, keeps z-index; the measure JS tests `=== 'sticky'`, so it still reads 0). Verified by addStyleTag.
- **The equal-weight buttons differ in height at 320/400%**: padding cap fixed "No thanks" (214px in a 256px sheet) but "Sure, that's fine" wraps to 3 lines, 310px, ring cut top and bottom (en, es, cs); the privacy link 301px too.
- **`audit-text-size.mjs` sets consent to declined unless `--banner`**: an author's "no findings" run without it never measured the sheet.
- Room: at 100% the sheet alone leaves 44-56% (45dvh cap), so the 768/200% sticky case (37-43%) costs only a few points more; acceptable.
- Body-size cookie text makes the sheet ~20% longer: at 320/200% "No thanks" is 1421px down a 256px scroll area (was 1076); at 400% 5652px. Inherent to text-before-buttons order; an owner trade-off, not a blocker.

**How to apply:** any change that makes a z-indexed element static: check every overlay that relied on its stacking (menus, dropdowns vs fixed sheets).
